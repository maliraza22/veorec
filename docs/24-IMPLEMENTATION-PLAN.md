**T-203 · Mirror new uploads to R2** — ✅ DONE (2026-09-10, code + integration verification; **the 1-week production acceptance window still has to be observed**). `server/r2mirror.js` mirrors the bytes of a *successful* legacy upload to `sources/rec_<legacyId>/source.<ext>` through `StorageProvider`, then records a `video_assets` row. **Behind `R2_MIRROR_UPLOADS` (default OFF — only the literal `true` enables it; when off the storage package is never loaded and the handler behaves exactly as before, so disabling is an instant rollback).** **Legacy stays authoritative:** the mirror runs after the response is sent, never throws into the request, and is asserted to leave an upload succeeding even with object storage unreachable. **Ordering:** the asset row is written on T-105's single FIFO lane via `dualwrite.recordingAsset()`, because `video_assets` has an FK to `recordings` and any other path would race its parent — the defect T-105 already hit. **Bytes first, row second:** a failed upload writes no row, so a row never claims a nonexistent object; the reverse leaves an orphan object, which is detectable and the safe direction. **Verified before the row is written:** the object is `HEAD`ed and its size compared to the uploaded byte count, so a truncated copy is never recorded as a good source. **Temp-file ownership** moves to the mirror in the Cloudinary branch (so the bytes survive long enough to stream) and it removes the file on every path including failure; in the local-disk branch `deleteAfter:false` — that file is the permanent legacy store, not a temp file. **Idempotent:** deterministic storage key + `assets.upsertSourceSystem()` (new repository method, `ON CONFLICT (storage_key)`) so a replayed mirror converges on the same row instead of violating the unique index, and an upsert can never re-point an object at a different recording. Bounded concurrency + queue shedding + durable journal `r2-mirror-failures.jsonl` (identifiers only, no credentials — asserted). KPI: `r2MirrorAttempt/Success/Failure` plus a `mirroredRatePct` that is exactly the acceptance number. Tests: `tests/r2mirror.test.js` (**43 assertions**: disabled-by-default and flag parsing, temp-file ownership both ways, real server + real MinIO + real PostgreSQL for object/size/bytes/row correctness, cross-user isolation, idempotency, invalid re-point, provider failure leaving the upload successful, journal hygiene, mirror-on/dual-write-off, cleanup). **Also verified end-to-end against real Cloudflare R2 staging**: a live upload produced the object at the expected key with matching size and byte-identical content, then was cleaned up. **T-204 · Backfill copier** — ✅ DONE (2026-09-10, code + integration verification; **the production backfill run itself is an operational step still to be performed**). `db/src/migration/backfill.js` + CLI `db:backfill` (**dry run by default**, `--apply` explicit, `--limit`/`--concurrency`/`--batch`). Copies each existing legacy original into R2 at `sources/{recordingId}/source.{ext}` via `StorageProvider` and records the `video_assets` row with `assets.upsertSourceSystem` (reused from T-203). **COPYING IS NOT CUTTING OVER:** a verified object is an ADDITIONAL copy — Cloudinary keeps serving every read, and the copier contains **no delete call of any kind** against either provider (asserted over the stripped source). No application read changed. **Checklist:** migration `0003_backfill_checklist.sql` extends `legacy.media_map` (the row T-104 created for this, per `07` §13) with `backfill_status` (`pending`/`claimed`/`verified`/`failed`/`skipped`/`unsafe`), `backfill_attempts`, `backfill_claimed_at`, `backfill_claim_id`, `backfill_retryable`, `backfill_bytes`, plus a CHECK making `verified` and `backfilled_at IS NOT NULL` equivalent so "the database says done" cannot drift from "the object was checked". **Claiming:** one atomic `UPDATE … FOR UPDATE SKIP LOCKED` — two workers never take the same row (asserted with concurrent claims), the claim commits **before** any byte moves so no transaction is held across a multi-minute transfer, and a crashed worker's claim **ages out** and becomes re-claimable. **Order:** claim → transfer (no txn open) → **verify by re-reading the object and comparing size** → asset row → checklist stamp. A crash between transfer and stamp converges on the next run because the key is deterministic and the row write is an upsert; the reverse order could claim an object that never landed. **Retry policy:** each item gets **one attempt per run** — an earlier draft re-claimed a transient failure inside the same loop, burning its whole attempt budget at once and hammering a provider already returning 5xx (found by testing, fixed). 5xx/429 retryable; 404/410, size mismatch, unsupported container and ambiguous mapping are **not**, and an attempt ceiling stops infinite retries. **Ownership is never guessed:** ambiguity → `unsafe` for human review; an existing object whose size disagrees with the legacy record is never overwritten; the upsert cannot re-point an object at another recording (asserted). **T-203 overlap:** a recording already mirrored is recognised via `headObject` and marked verified **without re-reading the legacy source** (asserted: zero legacy bandwidth). Tests: `tests/backfill.test.js` (**61 assertions**, real PostgreSQL + real MinIO) covering all 23 required scenarios. Also verified against **real Cloudflare R2 staging with synthetic fixtures** (object created, size matched, bytes identical, checklist stamped, cleaned up; staging left at 0 objects / 0 multiparts with T-202 config intact). Docs: `07` §19, `02` §2.7.4. **Acceptance NOT yet met:** "100% of non-deleted recordings have R2 sources" requires running the backfill against production data — the tooling is ready, the run is an operator action. **Deliberately NOT done:** no read cutover, no Cloudinary deletion or expansion, no upload-session API (T-301), no quota enforcement, no legacy JSON removal, no BullMQ/FFmpeg, no watch-page change.
